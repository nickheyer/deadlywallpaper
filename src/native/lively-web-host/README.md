# lively-web-host

Native Linux renderer for Lively's HTML / URL wallpapers. It loads a local page
or an online address in a WebKitGTK 4.1 web view, puts that view into a
`wlr-layer-shell` surface (through gtk-layer-shell) on the `background` or
`bottom` layer of one Wayland output, and talks to `Lively.Core.Linux` over
stdin/stdout with the JSON line protocol from `../PROTOCOL.md` (sections 1, 2,
3 and 5). Behaviour follows the Windows player `Lively.Player.WebView2/Form1.cs`
one for one: Shadertoy and YouTube URL conversion (`StreamUtil`), applying
`LivelyProperties.json` (`LivelyPropertyUtil.LoadProperty`), the JavaScript
bridge (`livelyPropertyListener`, `livelyWallpaperPlaybackChanged`,
`livelySystemInformation`, `livelyCurrentTrack`, `livelyAudioListener`),
pause/resume, mute, screenshots, pop-up and download handling.

## Files

| File | Purpose |
|------|---------|
| `main.c` | Window / layer surface, WebKit setup, stdin reader, message dispatch, pause snapshot, screenshots |
| `args.c/.h` | Command line parsing (`GOptionContext`), exit code 2 on any error |
| `ipc.c/.h` | JSON messages to the core (`msg_hwnd`, `msg_console`, `msg_wploaded`, `msg_screenshot`) |
| `stream_util.c/.h` | C port of `StreamUtil.TryParseShadertoy` / `TryParseYouTubeVideoIdFromUrl` |
| `props.c/.h` | C port of `LivelyPropertyUtil.LoadProperty` (control values from `LivelyProperties.json`) |
| `output_match.c/.h` | Maps `--output NAME` to a `GdkMonitor` through `zxdg_output_manager_v1` on GDK's `wl_display` |
| `test/` | Test wallpaper (`index.html`, `LivelyProperties.json`, `assets/`), `test.sh`, `stream_util_test.c` |

## Build

Requirements: gcc, make, meson, ninja, wayland-scanner, curl, pkg-config and the
development packages of `gtk+-3.0`, `webkit2gtk-4.1`, `json-glib-1.0`,
`wayland-client`. gtk-layer-shell is not required system-wide: `make deps`
downloads v0.9.2 from GitHub and installs it under `$(PREFIX)`
(default `<repo>/build/prefix`). The binary is linked with an rpath to
`$(PREFIX)/lib`, so it runs without any environment variables.

```
cd src/native/lively-web-host
make deps     # gtk-layer-shell v0.9.2 -> build/prefix (skipped when already installed)
make          # -> build/lively-web-host
make test     # unit test + live integration test on output DP-3 (LIVELY_TEST_OUTPUT overrides)
make clean
```

`BUILD_DIR` (default `build`) and `PREFIX` can be overridden on the make command line.

## Usage

```
lively-web-host --output NAME [--namespace NAME] [--layer background|bottom]
                [--span X,Y,W,H,VW,VH] [--interactive] [--property PATH] [--volume N] [--verbose]
                [--type local|online] [--debug PORT] [--color-scheme dark|light]
                [--pause-media] [--audio] [--sysinfo] [--nowplaying] [--pause-event]
                [--scale F] [--user-data DIR] <path-or-url>
```

`--type` defaults to `online` when the target has a URL scheme and `local`
otherwise. `--debug PORT` enables developer extras and the context menu, opens
the Web Inspector in its own window and starts WebKit's remote inspector HTTP
server on `127.0.0.1:PORT`.

Exit codes: 0 closed (`cmd_close`, stdin EOF, SIGTERM/SIGINT), 2 bad arguments,
3 no Wayland display / no `zwlr_layer_shell_v1` / no `zxdg_output_manager_v1`,
4 output not found or output removed, 5 WebKit view could not be created,
6 page could not be loaded (`msg_wploaded` with `Success:false` is sent first).

## Implementation notes

* Console messages: WebKitGTK 4.1 has no console-message signal, so a user
  script injected at document start (all frames) wraps `console.log/info/debug/
  warn/error` and the `error`/`unhandledrejection` events and posts them to the
  `lively` script message handler, which forwards them as `msg_console`
  (`Category` 2).
* Pause: `cmd_suspend` draws the web view into an image surface
  (`gtk_widget_draw`, which reads back WebKit's composited frame including
  WebGL, canvas and video), shows it in a `GtkImage` overlay and hides the
  `WebKitWebView`, so the page becomes `document.hidden` and its timers and
  animation frames stop while the last picture stays on screen. `cmd_resume`
  reverses this. `cmd_screenshot` uses the same capture (or the pause picture
  while paused) and saves it with gdk-pixbuf as jpeg / png / webp (png when the
  webp saver is missing) / bmp.
* Shadertoy: the wrapper page generated by `TryParseShadertoy` is loaded with
  the shader site's origin as base URI (`https://www.shadertoy.com/`) so the
  embed iframe is same-origin; Shadertoy's bot challenge answers with
  `X-Frame-Options: SAMEORIGIN` and would refuse to render inside an
  `about:blank` page.
* GDK is told to paint the toplevel through GL from the start (`GDK_GL=always`
  is set before `gtk_init`). Without it GDK's first paint uses an SHM buffer
  while Mesa has already registered explicit sync on the surface for WebKit's
  EGL surface, which KWin rejects as a protocol error.
* Span mode places the view inside a `GtkLayout` at `(-X,-Y)` with size
  `VW x VH`; the pause picture and screenshots take the same `(X,Y,W,H)` slice.

## Tests run

All of the following were run on Arch Linux, KDE Plasma 6.7 (Wayland), outputs
`DP-4` (2649x1490 at 0,136, scale 1.45) and `DP-3` (portrait 1080x1920 at
2649,0, scale 1), WebKitGTK 2.52.6, GTK 3.24.52.

```
make deps                       # gtk-layer-shell v0.9.2 built and installed into build/prefix
make                            # no warnings with -Wall -Wextra
make test                       # test/stream_util_test (24 cases) + test/test.sh: all checks passed
```

`test/test.sh` runs the host on `DP-3` with the test wallpaper and a scripted
stdin sequence (cmd_volume, every lp_* message, lsp_perfcntr, lsp_nowplaying,
lsp_audio, cmd_suspend, cmd_resume, cmd_screenshot to `$BUILD_DIR/shot.png`,
lp_button IsDefault, cmd_close) and asserts `msg_hwnd`, `msg_wploaded`
`Success:true`, the page's `console.log` text in a `msg_console`,
`msg_screenshot` `Success:true`, every property value echoed back by the page,
the playback event and `document.visibilityState` transitions, and that the PNG
has non-trivial content (PIL mean/stddev).

Manual runs with the same binary (`--verbose`, stdin fed through a fifo):

```
lively-web-host --output DP-3 --type online https://www.shadertoy.com/view/XsXXDn   (shader runs; two cmd_screenshots 4 s apart differ)
lively-web-host --output DP-3 --type online https://www.shadertoy.com/view/Ms2SD1   (Shadertoy answers the embed request for this
                                                  shader with info.usePreview=1 and its own embed script then shows the
                                                  static /media/shaders/Ms2SD1.jpg instead of compiling the shader)
lively-web-host --output DP-3 --type online --pause-media "https://www.youtube.com/watch?v=dQw4w9WgXcQ"
lively-web-host --output DP-4 --layer bottom --namespace lively-test-ns --span 0,136,2649,1490,3729,1920 test/index.html
lively-web-host --output DP-3 --color-scheme light --scale 2 --volume 100 --user-data /tmp/userdata test/index.html
lively-web-host --output DP-3 --interactive test/index.html      (WAYLAND_DEBUG=1: set_input_region(nil))
lively-web-host --output DP-3 --debug 9226 test/index.html       (inspector window + http://127.0.0.1:9226/)
lively-web-host --output HDMI-9 test/index.html                  -> exit 4
lively-web-host --output DP-3 --type local /nonexistent.html     -> exit 6
lively-web-host --output DP-3 --bogus test/index.html            -> exit 2

```

## Windowed preview mode

`--windowed WIDTHxHEIGHT [--title TEXT]` renders the page in a normal, decorated,
resizable window instead of a layer surface. The core uses it for wallpaper previews
and the add/edit wallpaper dialog. `--output`, `--span` and `--interactive` are ignored
(the window always receives input), the stdin protocol and screenshots work the same,
and the host exits with code 0 when the window is closed, on `cmd_close`, or on stdin EOF.

```
./build/lively-web-host --windowed 640x360 --title "Lively preview" test/index.html
```
